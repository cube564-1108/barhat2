# Код для сайта на 1С-Битрикс

Здесь лежит то, что **исполняется не у нас, а на сервере сайта** `barhatflowers.ru`.
В приложении на Amvera эти файлы не участвуют — их нужно скопировать на сайт руками.

## icml_fix_urls.php — пост-обработчик выгрузки каталога

Чинит ссылки на товары, которые уезжают в RetailCRM.

**Зачем.** Модуль `intaro.retailcrm` берёт ссылку у Битрикса запросом без фильтра
по разделу, а Битрикс на такой запрос отдаёт по строке на каждую привязку товара
к разделу — модуль берёт первую, то есть созданную раньше прочих. Основной раздел
товара при этом не участвует. Замер 2026-08-28: у 147 товаров из 456 ссылка
нерабочая; если первой привязкой стоит навигационный раздел («Все букеты», «Кому»,
«Событие») — сломано 165 из 165.

**Что делает.** Читает файл, сгенерированный модулем, и переписывает тег `<url>`
по одному правилу: ссылка выдаётся, только если у товара есть публичная страница
(элемент активен с учётом дат, раздел активен вместе с родителями), иначе тег
остаётся пустым. Адрес берётся по основному разделу — тому, по которому сайт строит
`<link rel="canonical">`.

Товары без страницы («Товары МС») из выгрузки **не убираются** — они нужны в CRM
для работы. У них просто нет ссылки, и админ не может отправить клиенту 404.

### Установка

1. Скопировать файл на сайт, например в `/bitrix/php_interface/icml_fix_urls.php`.
2. Прогнать вручную и посмотреть вывод:

   ```
   php /home/bitrix/www/bitrix/php_interface/icml_fix_urls.php
   ```

   Скрипт напечатает, сколько ссылок исправлено и очищено, и создаст рядом с
   исходной выгрузкой файл `retailcrm_fixed.xml`.
3. Проверить в нём несколько товаров — в первую очередь «Нежность»: в теге `<url>`
   должен стоять канонический адрес.
4. Поставить в крон **после** генерации ICML (она идёт около 19:30):

   ```
   40 19 * * * php /home/bitrix/www/bitrix/php_interface/icml_fix_urls.php
   ```
5. В RetailCRM (Администрирование → Магазины) заменить адрес файла каталога на
   `retailcrm_fixed.xml`.

Пути к исходному и итоговому файлам задаются переменными в начале скрипта.

### Что важно знать

- Из веба скрипт не запускается (проверка `PHP_SAPI !== 'cli'`) — он ходит по всему
  каталогу и переписывает файл, дёргать его извне незачем.
- Результат пишется через временный файл и `rename`: RetailCRM забирает выгрузку по
  расписанию и может прийти ровно в момент записи — полфайла она получить не должна.
- Если исходная выгрузка не обновлялась больше двух суток, скрипт пишет об этом
  предупреждение в лог: значит сломалась генерация у модуля, и в CRM уезжает
  устаревший каталог.
- Лог — `bitrix/catalog_export/icml_fix_urls.log` рядом с выгрузкой.

### Проверка результата

Со стороны дашборда за этим следит раздел **«Ссылки на товары»**: раз в сутки ночью
он обходит все ссылки из CRM и показывает, сколько из них сломано. Разовая проверка
руками — `python scripts/check_product_urls.py`.
