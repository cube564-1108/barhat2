# Оплата курьерам — разрезы отчёта

**Статус:** реализовано, на прод не выкладывалось
**Дата:** 2026-09-07

## Goal

Три доработки модуля «Оплата курьерам» по запросу владельца:

1. Отдельно выделить заказы в статусах группы «Отменён».
2. Заказы без курьера — отдельным списком с номерами заказов, а не одним числом.
3. Добавить распределение по салонам.

## Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Что считать «отменённым» | Группа статусов `cancel` из справочника `order_statuses` | Статусов отмены в CRM несколько («Отменён», «Отменён клиентом», «Не дозвонились»). Отбор по одному коду или по названию молча терял бы остальные |
| Входят ли отменённые в сумму к выплате | Нет, отдельный блок и отдельная KPI-плитка | «Выделить отдельно» = видеть, но не платить автоматически. Решение по каждому заказу принимает человек: курьер мог съездить |
| Какие отменённые показывать | Только те, где назначен курьер или потрачена себестоимость (`PAYOUT_FILTER`) | Отменённый самовывоз к выплатам отношения не имеет и только зашумил бы список |
| Что такое «салон» в распределении | `site_code` — сайт заказа в RetailCRM, название из `courier_sites` | От него же считается город в существующем фильтре, поэтому суммы разрезов сходятся между собой. `store_key` (склад-исполнитель) отвечает на другой вопрос — кто собирал букет, а не чей это расход на доставку |
| Как отдавать три новых блока | Одной ручкой `/api/couriers/report` вместе с отчётом | Каждая ручка — отдельное соединение с базой, а на сетевом диске `/data` цену определяет именно их число (CLAUDE.md). Четыре запроса вместо одного на каждый показ страницы |
| Откуда берётся список салонов для фильтра | Из `report.sites` того же ответа | Своя ручка означала бы и лишнее соединение, и скан всей витрины ради салонов «за все времена» — ровно то, чем 07.09 разогнали `/health` до 6–9 секунд |
| Прячет ли «только свои курьеры» заказы без курьера | Нет | Фильтр отсекает службы доставки. Заказы с непроставленным курьером — это дырка в CRM, которую как раз надо чинить, и прятать её фильтром нельзя |

## Что сделано

**`src/couriers/storage.py`**
- `CANCEL_STATUS_GROUP`, `DETAIL_LIST_LIMIT` — новые константы.
- `_period_filter(..., alias)` — префикс таблицы параметром вместо `.replace()`
  поверх готовой строки WHERE (тот приём сломался бы на любом новом условии,
  где встретится слово `delivery_date`).
- `_payout_scope()` — общий отбор (период, город, салон, `PAYOUT_FILTER`) без
  статуса: по статусу блоки расходятся, и общим остаётся только общее.
- `report_by_courier()` — плюс `site_code`, плюс блоки `sites`,
  `without_courier`, `cancelled`; всё одним соединением.
- `list_orders()` — плюс `site_code`, `cancelled`, название салона в строке.

**`src/couriers/server.py`** — параметры `site` и `cancelled` в `/report` и
`/report/orders`.

**`src/dashboard/index.html`** — фильтр «Салон», KPI-плитка «Отменённые», три
карточки (распределение по салонам, заказы без курьера, отменённые), колонка
«Салон» в модалке расшифровки.

**`src/dashboard/courier-payouts.js`** — отрисовка новых блоков, фильтр салона
(сужается по выбранному городу), расшифровка по салону, секции в CSV.

**`scripts/test_courier_payout_sections.py`** — сторож: отменённые не входят в
сумму выплаты, салоны сходятся с итогом, «без курьера» отдаётся списком, фильтр
«только свои» не прячет незаполненные заказы. 25 проверок.

## Ограничение, о котором нужно помнить

Витрина хранит все статусы только с 05.09.2026, а ночной глубокий прогон
перечитывает 90 дней назад. За периоды старше этого отменённые заказы будут
неполными — лечится кнопкой «Догрузить период».
