# Обратная связь от пользователей — план

**Дата:** 2026-09-02
**Статус:** [x] Реализован (фазы 1–7), не задеплоен. Фаза 8 (фото) — по итогам первого месяца
**Объём первого захода:** вариант B — рабочий минимум без AI-слоя

---

## Goal

Сотрудник из любого экрана дашборда за 15 секунд отправляет владельцу «что мешает»,
владелец разбирает поток одним экраном и превращает принятое в задачу бэклога —
без переписки в мессенджерах и без ручного пересказа задач агенту.

## Context

Половина инфраструктуры уже есть и переиспользуется:

| Что нужно | Что уже написано |
|---|---|
| Бэклог владельца, статусы, карточки | `src/tasks/` + секция «ЗАДАЧИ» на `/dashboard`, admin-only |
| Диалоги, работающие в iframe Пульса | `window.BarhatUI` из `src/dashboard/ui-dialog.js` |
| Перехват всех ответов сервера | обёртка `fetch` там же (`ui-dialog.js:432`) |
| Загрузка фото с телефона | `src/writeoffs/` — `ATTACHMENTS_DIR`, whitelist расширений |
| Роли и права | `ROLE_SECTIONS` в `src/auth.py` |

## Constraints

- Пользователи ходят через портал Пульс в `<iframe>` — нативные `alert/confirm/prompt`
  молча игнорируются, только `BarhatUI`.
- Диск `/data` на Amvera медленный (90–700 мс на запрос к базе) — виджет не имеет права
  делать запросы при загрузке страницы.
- Соединения только через `sqlite_conn.connect`, закрытие через `try/finally`.
- Пути к фото — только через `storage_paths.resolve`, резолв при импорте модуля.
- Вёрстка строго по `DESIGN-SPEC.md`: токены `--bx-*`, Vollkorn, без эмодзи.
- Текст пользователя показывается владельцу → экранировать `escapeHtml` (вариант с `"` и `'`).
- **Иерархия `z-index` дашборда уже занята:** гамбургер 1001, `.iv2-bulkbar` 1900,
  модалки 2000/2001, диалоги BarhatUI 100000.
- **У сессий из Пульса `SameSite=None`** (`_PartitionedSsoSessionInterface`,
  `src/pyrus/server.py:178`) — единственная CSRF-защита проекта на них не действует.

## Принятые решения

1. **Видимость — приватная.** Человек видит свои обращения и их статус. Чужие всплывают
   только как подсказка «похоже на это» при вводе — и **только после разбора владельцем**
   (см. критику фазы 1). Публичного борда и голосования нет.
2. **Уведомление владельцу — бейдж** с числом неразобранных. Ни почты, ни Телеграма.
3. **Точка входа — плавающая кнопка** на всех экранах, не пункт меню (шапка не подходит:
   `.content-header` скрыт в embed-режиме Пульса).
4. **Экран владельца — секция на `/dashboard`** рядом с «ЗАДАЧАМИ», admin-only через
   `role_required("admin")` на каждой ручке. Новый пункт меню и новое право не заводим —
   значит не трогаем `ROLE_SECTIONS`, `users.js` и навигацию.
5. **Обязательное поле одно** — «Что мешает?». Всё остальное собирается само.
6. **Спрашиваем про боль, а не про решение.** Второе поле «как хотелось бы» — необязательное.

**Сознательно не делаем в этом заходе:** публичный борд, голосование, SLA и сроки,
e-mail/Telegram-уведомления, AI-триаж и дайджест, автоприоритет по весу, фото
(вынесено в необязательную фазу 7).

## Фазы

### [x] Фаза 1 — Backend `src/feedback/`

- [x] `storage.py`: таблицы
  - `feedback_items`: `id`, `type` (`bug|inconvenience|wish`), `module`, `page_url`, `text`,
    `wish` (необязательное), `status` (`new|accepted|done|rejected|need_info` — пять,
    не шесть: `accepted` и `planned` на практике неразличимы),
    `author_username`, `author_role`, `created_at`, `updated_at`, `resolution`,
    `resolved_at`, `status_seen_by_author_at`, `merged_into_id`, `task_id`,
    `client_context` (JSON), `seen_at`
  - `feedback_supporters`: `feedback_id`, `username`, `created_at`
    + **UNIQUE(feedback_id, username)** — «у меня тоже» не должен задваиваться
  - Индексы по `status`, `module`, `created_at`, `author_username`
- [x] Все функции — `try/finally`, соединение через `sqlite_conn.connect`
- [x] Ограничение частоты: не более 10 обращений в час на автора.
      **Без `BEGIN IMMEDIATE`** — это не инвариант, а вежливый лимит: проскочившее
      11-е обращение никому не вредит, а write-лок общей базы стоит дорого
- [x] `server.py`, blueprint `/api/feedback`:
  - `POST /` — создать (любой авторизованный)
  - `GET /mine` — свои обращения со статусами и ответом владельца
  - `GET /similar?module=&q=` — похожие. **Отдаёт только `status != 'new'`**, то есть
    прошедшие через глаза владельца, плюс собственные обращения автора. Имена авторов
    не отдаются никогда
  - `POST /<id>/support` — «у меня тоже», `INSERT OR IGNORE`, идемпотентно
  - admin-only: `GET /` (очередь с фильтрами), `POST /<id>/status`, `POST /<id>/merge`,
    `POST /<id>/to-task`, `GET /<id>/export`
- [x] **Защита от CSRF:** на всех POST требовать заголовок `X-Requested-With: barhat`.
      Кросс-сайтовый `fetch` с кастомным заголовком уходит в preflight, который мы не
      одобряем. Нужно именно здесь: у SSO-сессий `SameSite=None`, и это ручка,
      доступная каждому сотруднику
- [x] `log_action` вызывать **после** коммита своей транзакции
- [x] `to-task`: сначала `tasks.storage.create_task` (своё соединение, свой коммит),
      только потом отдельным соединением `UPDATE feedback_items SET task_id`.
      Вложенных соединений не допускать

**Done when:** `flask test_client` — флорист создаёт и видит только свои; `/similar` не
отдаёт чужие обращения со статусом `new`; повторный `support` не создаёт дубль;
admin видит все; не-admin получает 403 на админских ручках; POST без `X-Requested-With`
отвергается.

## Pre-mortem: год прошёл, система не взлетела. Почему?

1. **Никто не пишет.** Кнопку не заметили, первого успеха не случилось.
   → Анонс на планёрке + первые 5 обращений закрыть в течение недели и показать результат.
   Один видимый «сделано по вашей просьбе» стоит десяти напоминаний.
2. **Очередь не разбирается.** Накопилось 80 «новых», открывать неприятно.
   → Бейдж считает только новые; массовое отклонение; честный статус «отложено» вместо
   молчания. Разбор — часть еженедельного круга.
3. **Поток ушёл не туда** — жалобы на графики, зарплату, коллег.
   → Формулировка вопроса про экран, тип обращения, отдельный ответ «не про дашборд».
   Здесь же вторая причина, по которой `/similar` не показывает неразобранное.
4. **Дубликаты съели смысл.** 30 записей про одно.
   → Дедуп при вводе плюс «Объединить» на экране владельца. С учётом правки фазы 1
   первую неделю дедуп держится только на владельце — это принятая цена приватности.
5. **Виджет замедлил дашборд.** Лишний запрос на каждой загрузке на медленном `/data`.
   → Ноль запросов до клика; счётчики — внутри уже существующего `/api/auth/me`.
6. **Утекли данные.** Техбуфер приложил ответ с чужими персональными данными.
   → Сохраняем только код, путь и поле `error`; auth-ручки исключены; техконтекст
   виден только автору и админу.
