# Экраны дашборда — родными модулями Пульса, по одному

**Статус:** черновик, фазы не начаты
**Редакция 3:** 22.09.2026, по ответу Романа — экран читает `core`, данные переезжают первыми
**Владелец:** Стас · **Согласовано:** Роман, 22.09.2026
**Предшествует:** `plans/2026-09-15-переезд-дашборда-в-общую-среду.md` (шаги 1–4)

## Цель

Экраны становятся родными страницами Пульса: читают схему `dashboard` в `barkhat-core`,
а действия (открыть смену, списать товар, отправить в банк) отдают командой сервису
дашборда. Обработка и внешние системы остаются в сервисе. Ни один действующий модуль не
останавливается.

## Что изменилось в редакции 3

Я предлагал переходный режим: страница Пульса читает **API сервиса**, тогда перенос экрана
не требует переноса данных — как было при переходе «Счета» → «Согласование счетов».
**Роман отклонил:** переезжаем по правилам среды, экран Пульса читает `core`.

Практическое следствие: **данные модуля едут в core ДО его экрана.** Порядок обратный
тому, что был в редакции 2.

Бесшовность от этого не теряется, но держится другим:

| Держит бесшовность | Как |
|---|---|
| Выгрузка базы существует до первой миграции | Шаг 1 плана переезда — делается первым |
| Данные едут по одному модулю | Остальные продолжают жить на SQLite |
| Файл SQLite не удаляется | Откат переключения модуля на Postgres |
| Пока данных нет в core — экран в iframe | Работает как сегодня, никто не ждёт |
| Оба пункта меню на время обкатки | Переключение без деплоя, откат за секунды |
| Старый экран и его код не удаляются | Как не удалён `invoices.js` |

## Предусловие для каждого модуля

**Экран не начинают переносить, пока таблицы модуля не в схеме `dashboard` и модуль не
переключён на Postgres** (шаг 4 плана переезда). Иначе странице Пульса нечего читать.

### «Показатели салонов» — не дубль аналитики, но требуют подписи

Роман проверил: `analytics.sal_*` — выручка, заказы, средний чек, YoY/LFL по салону и

У нас — отгрузки «Выполнен» по дате **доставки** против плана, плюс «Улица», Pyrus, такси,
МойСклад. Расчёт переносим свой.

## Как устроен модуль Пульса (образец «Акции», `/promo`)

| Что | Где |
|---|---|
| Пункт меню | `components/layout/Sidebar.tsx`, строки 114–124 — `{href, label, icon, moduleKey}` |
| Права | `lib/pulse/sections.ts` — строка в `PULSE_MODULES`; галочка на `/access` появляется сама, выдаётся без деплоя |
| Гард страницы | `app/promo/layout.tsx` — `getCurrentPayrollUser` + `ensurePulseAccess` → 404 |
| Гард API | `requireApiModule("<ключ>")` из `lib/pulse/access.ts` → 403 |
| Данные | `app/promo/page.tsx` — серверная страница, читает `lib/promo/queries.ts` под `withUserContext` (RLS) |
| Кнопки | серверный роут Пульса зовёт сервис; образец вызова — `lib/reconcile/proxy.ts` |
| Компоненты | `components/layout/` (PageContainer, PageHeader, BarkhatMark); свои — в `components/<модуль>/`; UI-кита нет |
| Библиотеки | lucide-react, recharts (только `dynamic(..., { ssr: false })`), @dnd-kit, exceljs |
| Токены | `app/globals.css` + `tailwind.config.ts` |
| Стек | Next 15, React 19, TypeScript, Tailwind |

**Грабли от Романа:** сегменты маршрутов только латиницей (кириллица = 404 за прокси);
эмодзи в интерфейсе нет.

**Локальный запуск:** `platform/CLAUDE.md` → «Локальный запуск», пароль `svc_platform_ro`
даёт Роман.

**Важно для оценки:** стек другой — JS переписывается, а не переносится. Цену модуля меряем
на пилоте, до этого любая оценка в строках — это счёт старого кода, а не новой работы.

## Деплой — решено: вариант (а)

Свои разделы Пульса Стас выкатывает сам, без спроса. Правила общие для троих:

- **В `main` Пульса только готовое к выкатке.** Смержил в `main` — любой может это
  выкатить; незаконченное держим в ветке.
- **Перед деплоем:** `git log --oneline amvera/master..main`. Едет чужое — одна строка
  владельцу: «выкатываю Пульс, заодно едет твоё X». Предупредить, не спрашивать.
- **Свои модули — в своих папках:** `app/<модуль>`, `components/<модуль>`, `lib/<модуль>`.
- **Общее — через PR, смотрит Роман:** `app/layout`, `Sidebar`, `middleware`, `lib/auth`,
  `lib/pulse`, `db/`, `package.json`. Пункт меню и строка в `sections.ts` — не в счёт,
  достаточно сказать.
- **После деплоя проверить живой Пульс:** вход, главная, свой раздел. Сломалось — revert
  и выкатить заново.

## Конвейер одного модуля

| Шаг | Что делаем | Done when |
|---|---|---|
| 0 | Данные модуля в `core`, модуль на Postgres, SQLite цел | Сверка строк и сумм сошлась |
| 1 | Разбор: что экран показывает, какие права проверяет, какие действия зовёт | Список на бумаге |
| 2 | Страница в Пульсе + строка в `PULSE_MODULES` + пункт меню; доступ только Стасу | Открывается, цифры сходятся со старым экраном |
| 3 | Действия: серверный роут Пульса → ручка сервиса; права продублированы на сервере | Без прав отбивается в обоих местах |
| 4 | Пилот: Стас + один управляющий | Неделя без возвратов |
| 5 | Доступ всем; в меню оба — новый раздел и старый iframe-пункт | Обе страницы доступны |
| 6 | Старый iframe-пункт выключен на `/external/manage` | Две недели и пик пройдены |
| 7 | Старый экран остаётся архивом; код не удаляем | — |

**Откат на любом шаге:** включить старый пункт на `/external/manage` — без деплоя,
секунды. Новый раздел закрывается снятием галочки на `/access`, тоже без деплоя.

**Точки невозврата нет.**

## Правила на время перехода

- **Один модуль в работе.** Пока текущий не дошёл до шага 6, следующий не начинаем.
- **Пока модуль на шагах 2–6, правка вносится в оба экрана или откладывается.**
- **Критический баг чинится в старом экране первым** — он боевой.
- **Денежный экран не переключаем в конце месяца**, сменный и складской — не в праздник.
- **Сторожа модуля** (`scripts/test_*.py`) прогоняются на новом экране и на Postgres.

## Когда возвращаемся назад

Возврат — нормальный исход шага, а не ЧП:

- цифры разошлись со старым экраном;
- новый экран заметно медленнее;
- человек говорит «на старом было удобнее» и это не вкусовщина;
- любая ошибка в действии, меняющем деньги или остатки.

## Порядок модулей

Определяется позже, но три ограничения действуют всегда:

- **От безопасного к денежному:** качество, оплата курьерам, показатели → загрузка
  салонов, контроль доставки, списания → кассовые смены, счета.
- **Кассовые смены — после того,** как гонка открытия смены переехала на механизм
  Postgres и сторож `test_shift_open_race.py` зелёный на нём.
- **Счета — подэтапами:** список, карточка, распределение, согласование, платёжка в банк,
  разноска в ПланФакт. Один подэтап = одна поставка.

## Риски

| Риск | Что его держит |
|---|---|
| Сломали работающий модуль | Экран переносится только после того, как данные переехали и обкатались |
| Цифры разошлись | Сверка со старым экраном за один период — условие шага 2 |
| Новый экран хуже, а старого нет | Старый iframe-пункт включается на `/external/manage` за секунды |
| Гонка открытия смены сломалась на Postgres | Модуль последним, сторож гоняется на Postgres |
| Права по салонам потерялись | RLS по салонам сотрудника; механизм отрабатывается на пилоте |
| Оценка обманула | Стек другой, JS переписывается; меряем на пилоте, а не считаем строки |
| Управляющие сверяют «Показатели» с «Продажами» | Подпись на экране про дату доставки и статус |
