# Перенос модулей дашборда в БАРХАТ Пульс (вариант 3, помодульно)

**Статус:** черновик, фазы не начаты
**Владелец:** Стас · **Требует согласования:** Роман (Пульс, ядро базы, реестр модулей)
**Зависит от:** `plans/2026-09-15-переезд-дашборда-в-общую-среду.md` (фазы B и C)
**Правила:** `.business/команда/как-работаем-с-ai.md` → «Мозги и лицо», «Работа с общей базой»

> По правилам команды фича такого размера начинается с `IDEA.md` через Deep Research, и только
> потом появляется план. Этот документ — рабочий план порядка и конвейера; решения об объёме
> (что переносим, что сливаем, что удаляем) в разделе «Реестр модулей» нужно подтвердить с
> Романом до начала первой фазы.

## Цель

Модули дашборда перестают быть внешним сервисом в `<iframe>` и становятся модулями Пульса:
экраны — страницы Пульса, читают готовые витрины из `barkhat-core`; обработка, синки и походы
во внешние системы остаются сервисом дашборда, который Пульс вызывает по команде.

**Готово, когда:** ни один экран не открывается через iframe; сервис дашборда не отдаёт HTML,
только API и фоновые задачи; `src/dashboard/` удалён из репозитория.

## Почему помодульно, а не целиком

24 600 строк фронтенда в 17 экранах. Переписывание «одним куском» означает месяцы без
поставки и невозможность откатиться. Помодульный конвейер даёт три вещи: каждый шаг сам по
себе полезен, каждый откатывается отдельно, и после первого модуля становится известна
реальная цена следующего.

## Жёсткая предпосылка, которую нельзя обойти

**Пульс не имеет права ходить в источники и делать тяжёлые расчёты на рендере** — он читает
готовые витрины. Значит экран нельзя перенести раньше, чем его данные окажутся в
`barkhat-core`. Порядок для каждого модуля всегда один: **сначала данные, потом экран.**

Отсюда: фаза C переезда (SQLite → core) — не «соседняя задача», а часть этого плана. Она
делается не целиком заранее, а **по одному модулю**, вместе с его экраном.

## Принципы переноса

1. **Мозги остаются, переезжает лицо.** Расчёты, синки, запись во внешние системы
   (МойСклад, РетейлКРМ, Модульбанк, ПланФакт) остаются сервисом. Пульс показывает и
   командует.
2. **Два экрана живут параллельно.** Новый модуль Пульса и старый экран работают
   одновременно, пока новый не обкатан. Переключение — правами, а не удалением кода.
3. **Удаление старого — отдельный шаг** и только после недели работы нового без замечаний.
4. **Одна витрина = один писатель.** Витрину модуля пишет сервис дашборда, Пульс её только
   читает. Ничего не пишем в чужие схемы и в зеркало.
5. **Действия — командой сервису.** Кнопка в Пульсе не пишет в базу напрямую: она зовёт
   ручку сервиса, тот исполняет и отвечает. Иначе инварианты (гонки смен, НДС в платёжке,
   обязательные вложения) окажутся в двух местах сразу.
6. **Проверять на реальных данных.** Экран считается перенесённым, когда цифры на нём
   совпали со старым экраном за один и тот же период, а не когда он «открылся».

## Конвейер одного модуля (шаблон, повторяется для каждого)

| Шаг | Что делаем | Done when |
|---|---|---|
| 1 | Инвентаризация: какие таблицы читает экран, что пишет, куда ходит наружу | Список таблиц и внешних вызовов на бумаге |
| 2 | Решение: переносим / сливаем с существующим модулем Пульса / оставляем / удаляем | Решение записано в реестр ниже, согласовано с Романом |
| 3 | Таблицы модуля → схема `dashboard` в core (DDL, миграция данных, сверка counts и `max(updated_at)`) | Цифры в core совпадают с SQLite до строки |
| 4 | Сервис пишет в core, SQLite остаётся живым для отката | Сутки двойной записи без расхождений |
| 5 | Витрина под экран: считает сервис, Пульс читает готовое | Запрос экрана — один SELECT по индексу, не агрегация на лету |
| 6 | Экран как модуль Пульса: страница, права (ACL Пульса), дизайн по токенам Пульса | Экран открывается, цифры сходятся со старым за тот же период |
| 7 | Действия: кнопки зовут ручки сервиса, права продублированы на сервере | Каждое действие отбивается без прав и на клиенте, и на сервере |
| 8 | Переключение: пункт меню ведёт в Пульс, старый экран скрыт правом | Неделя работы без замечаний |
| 9 | Удаление: старый экран, его JS, его ручки HTML | `src/dashboard/<модуль>.js` удалён, тесты зелёные |

**Откат на любом шаге:** до шага 8 — вернуть людей на старый экран (он жив); после 8 и до 9 —
вернуть право; после 9 — восстановить из git.

## Реестр модулей: что переносим, а что нет

Не всё нужно переписывать. Часть экранов дублирует то, что в Пульсе уже есть, часть не имеет
смысла внутри Пульса вообще.

| Модуль | Строк JS | Решение | Почему |
|---|---|---|---|
| ABC-анализ | 402 | **Пилот** | Маленький, только чтение, никто не пострадает при сбое |
| Слежение за ссылками | 227 | **Слить с SEO-модулем Пульса** | В Пульсе есть раздел SEO со своими витринами `seo_*` — держать второй смысла нет |
| Задачи | 297 | **Слить с задачником Пульса** | В ядре есть схема `tasks` и задачник; два задачника — источник путаницы |
| Показатели салонов | 931 | Переносим | Только чтение, витрина считается сервисом |
| Отчёт по качеству | 855 | Переносим | Только чтение; им уже пользуется директор через Пульс |
| Калькулятор букета | 1 394 | Переносим | Считает на клиенте, внешних вызовов нет |
| Загрузка салонов | 1 871 | Переносим | Чтение + ввод норм; помнить про единицы измерения |
| Оплата курьерам | 859 | Переносим | Чтение + расчёт; расчёт остаётся в сервисе |
| Обратная связь | 968 | Переносим | Простая запись в свою схему |
| Списания | 1 376 | Переносим, поздно | Фото, сжатие на клиенте, необратимое списание в МойСклад |
| Кассовые смены | 1 833 | Переносим, поздно | Деньги, гонки открытия смены, `BEGIN IMMEDIATE` |
| Счета (согласование) | 7 496 | Переносим последним | Треть всего фронтенда, деньги, банк, ПланФакт, НДС |
| Счета (старый архив) | 1 832 | **Удалить, не переносить** | Уже скрыт у всех, кроме админа; переносить архив незачем |
| Управление пользователями | 813 | **Удалить, не переносить** | После переезда сотрудники и права живут в `app` Пульса — свой список станет вторым источником правды |
| Приложение курьера (PWA) | 1 324 + SW | **Оставить как есть** | Это не экран офиса: телефон курьера, оффлайн, push, установка на домашний экран. Внутри Пульса ему делать нечего |
| Диспетчер доставки | 671 | Переносим | Экран управляющего, место ему в Пульсе |

**Итого:** переносится 10 экранов, сливается 2, удаляется 2, остаётся снаружи 1.
Из 24 600 строк реально переписывается около 18 000, и почти половина — счета.

- [ ] Согласовать с Романом: схема `dashboard` в core, роль `bh_dashboard_writer`, логин
      `svc_dashboard`; кто заводит витрины; как Пульс зовёт ручки сервиса (Bearer?)
- [ ] Согласовать реестр выше: что сливаем, что удаляем
- [ ] Выбрать и зафиксировать пилот (предложение: ABC-анализ)
- [ ] Договориться о правиле переключения: как держать оба экрана и чем переключать

**Done when:** известно, как выглядит «модуль Пульса», и с Романом согласован объём.

### Фаза 1 — пилот: ABC-анализ

Весь конвейер из 9 шагов на самом безопасном модуле. Цель фазы — не экран, а **измеренная
цена одного модуля**: сколько занял перенос данных, сколько экран, где вылезли неожиданности.

- [ ] Шаги 1–9 конвейера
- [ ] Записать фактические трудозатраты по шагам
- [ ] Поправить конвейер по опыту, до того как он применён к девяти модулям

**Done when:** ABC-анализ открывается из меню Пульса, цифры сошлись, старый экран удалён,
конвейер уточнён.

### Фаза 2 — модули только на чтение

Показатели салонов · Отчёт по качеству · Калькулятор букета · Оплата курьерам.
Ошибка здесь показывает неверную цифру, но ничего не ломает.

- [ ] По конвейеру, по одному
- [ ] Сверка цифр со старым экраном за один период — обязательна для каждого

### Фаза 3 — слияние дублей

- [ ] Слежение за ссылками → в SEO-модуль Пульса
- [ ] Задачи → в задачник Пульса (схема `tasks`)
- [ ] Удалить старый раздел счетов (архив) и управление пользователями,
      перевести учётки на `app.employees` Пульса

**Осторожно:** удаление управления пользователями трогает вход в дашборд. Делать после того,
как права модулей уже выдаются в Пульсе, иначе потеряется доступ у всех сразу.

### Фаза 4 — модули с записью

Загрузка салонов · Обратная связь · Диспетчер доставки · Списания.

- [ ] По конвейеру, по одному
- [ ] Для каждого действия — проверка прав на сервере, не только в интерфейсе
- [ ] Списания: фото, сжатие на клиенте, дозагрузка в карточке, запрет удаления последнего
      обязательного вложения — переносить целиком, а не «основной сценарий»

### Фаза 5 — деньги

Кассовые смены · Счета (согласование).

- [ ] Кассовые смены: перенести вместе с инвариантом «проверил → записал = одна транзакция»
      (`BEGIN IMMEDIATE` + уникальный индекс + блокировка кнопки)
- [ ] Счета: разбить на подэтапы — список, карточка, распределение, согласование, платёжка
      в банк, разноска в ПланФакт. Один подэтап = одна поставка
- [ ] НДС, реквизиты плательщика, сохранённые платёжки — переносить как есть, не «упрощать»

### Фаза 6 — гашение

- [ ] Сервис перестаёт отдавать HTML, остаются только API и фоновые задачи
- [ ] Удалить `src/dashboard/` (кроме приложения курьера)
- [ ] Убрать SSO-вход через iframe, снять `frame-ancestors`
- [ ] Обновить `CLAUDE.md` сервиса: это теперь «мозги» без «лица»

**Done when:** прямой заход на адрес дашборда не открывает ни одного экрана.

## Риски

- **Экран переписан раньше, чем данные уехали в core** — придётся переписывать дважды.
  Лечится жёстким порядком «сначала данные».
- **Два источника правды по правам.** Пока живут и `users` дашборда, и `app.employees`
  Пульса, человек может иметь доступ в одном и не иметь в другом. Фазу 3 не затягивать.
- **Инвариант потерялся при переписывании.** Гонка смен, НДС из поля а не из названия,
  единицы измерения в загрузке салонов, обязательное вложение у списаний — всё это
  добыто болью и в новом коде должно быть воспроизведено. Для каждого есть сторож в
  `scripts/` — сторожа переносить вместе с модулем.
- **Оценка «по первому модулю» обманет.** ABC-анализ в 18 раз меньше счетов. Считать не
  «модулей осталось», а «строк осталось».
- **Пульс и дашборд разъедутся по данным** в период двойной жизни экранов. Сверять не
  глазами, а запросом, и по одному периоду.

5. Подтвердить, что приложение курьера остаётся снаружи Пульса.
