## Упрощения после критики

| Было | Стало | Почему |
|---|---|---|
| SQLAlchemy ORM | sqlite3 напрямую | MVP проще без ORM |
| Пагинация в Фазе 2 | Убрано | Добавим когда понадобится |
| FastAPI + CORS | Простой endpoint | Достаточно JSON по ссылке |
| Прогресс-бар | Убрано | Избыточно для MVP |
| Тесты в Фазе 6 | Перенесены | Сначала сделаем, потом протестируем |

## Предотвращение рисков (Pre-mortem)

| Риск | Решение |
|---|---|
| SQLite станет мал | Гибкая схема → легко мигрировать в PostgreSQL |
| Pyrus rate limits | Batch запросы + кэширование |
| Данные устареют | Ручное обновление + timestamp в БД |
| Endpoint станет медленным | Встроенный кэш + индексы |

**Структура проекта:**
```
src/pyrus/
├── __init__.py
├── client.py      # REST-клиент Pyrus API
├── fetcher.py     # Загрузка с retry
├── storage.py     # SQLite с историчностью
├── server.py      # Flask JSON API
└── README.md      # Документация

scripts/
└── update_pyrus.py # Скрипт обновления
```

**Использование:**
1. Настроить `.env` (PYRUS_LOGIN, PYRUS_SECURITY_KEY)
2. `python scripts/update_pyrus.py` — загрузка данных
3. `python -m pyrus.server` — запуск API для дашборда

**Что изменилось по ходу:**
- Заменили pyrus-api на свой REST-клиент (проблемы с установкой на Python 3.14)
- Убрали SQLAlchemy, используем sqlite3 напрямую
- Упростили CORS — не нужен для JSON по ссылке
